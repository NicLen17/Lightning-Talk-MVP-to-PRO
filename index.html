El contexto

Registrar un partido a mano

Anotar un partido de vóley en papel implica registrar cada saque, recepción, ataque y error — jugador por jugador, rally tras rally, sin pausa.

  • Un set supera las cien acciones; entre punto y punto quedan segundos.
  • Hay que mirar la cancha y escribir al mismo tiempo.
  • Se pierden acciones, hay errores de numeración o te quedás atrás.
  • A esa velocidad, hacerlo a mano es humanamente inviable.

Tenemos definido el requerimiento: capturar datos mientras el partido sigue, sin perder el ritmo.

Introducción

Sistema de scouting

Un módulo de scouting reemplaza la planilla manual: registra acciones de cada jugador en vivo para generar estadísticas, tendencias y material de análisis durante y después del partido.

Requerimiento: capturar decenas de acciones por set sin perder el ritmo del partido. Pregunta de diseño: ¿qué interfaz lo hace posible?

La tesis central

Minimalista ≠ Mejor UX

La regla clásica del diseño dice: menos es más. Interfaz limpia, carga cognitiva baja, curva de aprendizaje suave.

Pero en entornos profesionales de alta exigencia — como el deporte en tiempo real — esa regla se rompe.

Aumentar la complejidad visual y saturar la pantalla intencionalmente puede ser el camino correcto para maximizar la velocidad del usuario experto.

Fase 1 — MVP Tabular Tabla clásica, curva cero, operación lenta
Fase 2 — Salto Espacial Mapeo mental directo, aire desperdiciado
Fase 3 — Herramienta Pro Eficiencia operativa máxima, símbolos internacionales
FASE 1

MVP Tabular

  • Solución inicial: Una planilla técnica tradicional. Botones de "+" y "−" para fundamentos básicos como puntos, aces, bloqueos y errores.
  • Experiencia (UX): Curva de aprendizaje casi nula. Altamente intuitiva para cualquier usuario — si sabés leer una tabla, sabés usarla.
  • El límite real: Inviable para el ritmo frenético del vóley en vivo. Falta contexto espacial: el scouter piensa en zonas y jugadores en cancha, no en filas de una planilla.
  • Veredicto: Cumple el requisito a nivel de código, pero falla operativamente bajo presión de partido.
FASE 2

Salto Espacial

Mapeo Mental Directo

  • El salto conceptual: Pasamos de leer una lista de nombres a tocar zonas de una cancha en vivo. El analista asocia al jugador con su posición real en el campo.
  • Más contexto en pantalla: Zonas por número, nombres completos de jugadoras, acciones con descripciones de cada valoración y botones grandes para interactuar.
  • El límite del diseño web: Aun así, la interfaz seguía atada a patrones tradicionales: paddings, márgenes y espacios en blanco que no aportaban al scouter. El error fue tratar el scouting como un diseño web genérico.
  • El cuello de botella: La distancia del mouse entre seleccionar jugador y registrar la acción consume fracciones de segundo críticas en cada rally — demasiado aire desperdiciado para el ritmo del partido.
FASE 3

Herramienta Pro

Eficiencia Operativa Máxima

  • Diseño 100% de nicho: Dejamos atrás patrones clásicos de UI por un desarrollo personalizado al usuario experto — símbolos internacionales #, +, /, −, = en grilla densa por tipo de acción.
  • Menos ayuda, más velocidad: La curva de aprendizaje sube respecto a la Fase 2: desaparecen descripciones, nombres de jugadoras y texto explicativo de las valoraciones.
  • El trade-off: Para el analista profesional es la herramienta definitiva; el usuario promedio queda fuera de la ecuación. Menos alcance, pero infinitamente más útil para la captura de datos específica.
  • Filosofía UX: Minimizar el movimiento del cursor y maximizar atajos de teclado. La UX prioriza performance sobre legibilidad — un clic por acción, todo visible de un vistazo.

La lección

Ninguna versión es “la mejor”

Las tres iteraciones cumplieron su propósito. Cuál conviene depende del usuario al que apunten — no de cuál sea la más reciente.

Tres públicos, tres herramientas

La Fase 1 la puede usar casi cualquiera — ideal para alguien de una federación que registra a grandes rasgos un partido y su resultado. Para ese usuario, las fases 2 y 3 no le servirían: más datos no ayudan si no puede operarlos.

La última no siempre gana

La Fase 3 reduce quién puede usarla, pero es infinitamente más útil para el experto y la captura de datos específica. Como desarrolladores tendemos a asumir que la versión final es la mejor — este caso demuestra lo contrario.

El usuario define

No podemos decidir desde el código cuál interfaz es mejor. Cada iteración intercambia accesibilidad por profundidad — y eso lo elige el operador y el dominio, no el desarrollador solo.

Conclusiones

Construir en público

No teoría de manual — el barro real de iterar un producto en producción, con decisiones difíciles entre UI atractiva y UX eficiente.

Tres iteraciones, tres lecciones

Tabular → Espacial → Pro. Cada fase resolvió un problema y creó otro. La iteración no es fracaso, es el proceso.

UI atractiva vs. UX eficiente

A veces ganan los controles saturados. Una interfaz saturada puede ser la mejor experiencia de usuario si el dominio lo exige.

Escalar con el usuario

La UI debe escalar en complejidad junto con la expertise del operador. No hay que tenerle miedo a saturar la pantalla.

El mejor diseño no es el más bonito. Es el que permite al usuario experto trabajar más rápido.
